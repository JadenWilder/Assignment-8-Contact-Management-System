**Design Memo: Contact Management System**

A hash table is an effective data structure for a contact management system because it allows contacts to be located quickly using their names as keys. Instead of checking every contact one by one, the system applies a hash function to convert a name into an array index. This makes searching and inserting efficient on average, even when the system contains hundreds or thousands of contacts. A hash table is especially useful for devices with limited memory and no built-in database because it can store and retrieve information without requiring a complex database system.

In my implementation, I used separate chaining to handle collisions. A collision happens when two different contact names produce the same array index. Each position in the array can store the first node of a linked list. When a new contact collides with an existing contact, the new node is added to that position's linked list. During a search, the program calculates the index and traverses the linked list until it finds the matching name or reaches the end. If a contact with the same name is inserted again, the system updates the existing phone number instead of creating a duplicate entry.

An engineer might choose a hash table over a list when fast lookups are important, because searching an unsorted list may require checking every element. A hash table can provide average-case constant-time insertion and searching when the hash function distributes keys effectively. A tree may be preferable when sorted data, ordered traversal, or range queries are required. Overall, this implementation demonstrates how hashing, arrays, and linked lists work together to provide efficient contact storage and retrieval.
